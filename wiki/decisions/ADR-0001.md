# ADR-0001: single source of truth per object

**Date:** 2026-10-28. **Decision:** adopted.

Problem: many agents edit README, MOCs and to-do notes independently. Conflicting completion claims and forgotten interface assumptions accumulate.

Decision:
1. GitHub Issues are canonical for work items, progress and acceptance evidence. `wiki/tasks.md` is a dated *navigation view*.
2. Git commit history + `wiki/log.md` capture developer operation provenance. Runtime source snapshots and job logs remain in `data/` and Actions, not human-knowledge text.
3. `wiki/_index.md` and MOCs are navigation; concepts and manifests hold substantive content once each.
4. Important architecture decisions live in permanent ADR pages; obsolete decisions are superseded, never erased.
5. `wiki/operations/HANDOFF.md` holds current verified working state, not claims inferred from unexecuted workflows.

Consequences: one extra documentation step per tested feature; lower inter-agent drift and a trail for adversarial inspection. Do not mirror a full issue status history into Markdown.
