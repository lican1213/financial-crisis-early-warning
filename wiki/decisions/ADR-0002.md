# ADR-0002: notification and evidence boundary

**Date:** 2026-10-28. **Decision:** adopted.

Problem: hourly full reports constitute noise even when four user-defined alert triggers are absent. Disparate market variables can overcount one episode. A GitHub issue may be mistaken for delivered crisis notification.

Decision: default to silence; inspect fresh source timestamps; aggregate correlated readings into families; record new candidate incidents once; compare with explicitly sourced weekly baseline; suppress duplicate alerts; require a verified transport layer for end-user pushes. Temporary `verified=true` event flags require manual operational scrutiny before any external notification.

Consequence: the v0.2 prototype can propose GitHub candidate issues but **does not** independently validate all event claims or control existing ChatGPT automations. Historical threshold tuning remains a research task.
