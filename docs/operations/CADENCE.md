## Delivery boundary
The daily research workflow publishes its official observations **before** rebuilding and committing the read-only ChatGPT feed. An initially stale feed after NBS succeeded revealed a real ordering defect (FAIL-045). The bridge refresh is a separate post-persistence step; GitHub can still produce concurrent update conflicts, which must fail visibly rather than be interpreted as a market crisis. [Run and audit evidence](../../wiki/operations/INCIDENTS.md).

The [read-only ChatGPT bridge](../../src/fcews/bridge.py) exposes only research snapshot freshness, source observation dates, and null China/company scores. Even a fabricated `notification_authorized=true` field in a research file cannot authorize an alert; [bridge regression tests](../../tests/test_bridge.py) prove the separation.

The research workflow is context-only and never increases independent systemic stress families or sends ChatGPT notifications. Official-host acceptance of a manually entered China/company release is not proof of the numeric statistic; verify underlying tables before claims. See [leading research gate](../../wiki/datasets/leading-research.md).

The [ChatGPT feed](../../data/chatgpt_feed.json) is **poll-only**, not a push event or confirmed end-user receipt. [GitHub Issue canary #11](https://github.com/lican1213/financial-crisis-early-warning/issues/11) verifies GitHub create/read/close only; ChatGPT cannot emit an exact-once acknowledgement to the repository. The hourly ChatGPT task remains enabled. We deliberately keep user-visible responses silent without one of the four qualifying systemic changes.

## Data quality gates
A GitHub Action run marked success is not sufficient evidence of market source coverage; inspect `data/health.json`. **degraded** means fewer than three fresh live independent risk families, an operational incident, not calm markets. Context-only Cboe/MOVE substitutes do not independently increase family counts until calibration. No private holdings, credentials or user-specific assets are committed to the currently public GitHub repository.

### 2026-11-06 operational guardrails
- A **healthy** collection needs all four actual live families (system, credit, volatility, funding), no unresolved collection errors and no unusually old official source dates. Three live families, or an overdue series, are **partial**; fewer than three are **degraded**. Missing live evidence is not filled by cached observations. An FRED SOFR/TGCR request may fail while the same series is successfully collected from the independent official NY Fed endpoint (and vice versa); the original error is retained under `recovered_source_errors`, not confused with unavailable data.
- [Source age check](../../src/fcews/quality.py) flags daily observations more than **three weekdays** behind and weekly observations more than **eight weekdays** behind as **operational heuristics**. The count excludes weekends but not public holidays or publisher-specific release calendars; it does not claim an exact publication timestamp and cannot trigger a market-risk alert.
- [Actual schedule delivery audit](../../src/fcews/schedule_health.py) checks the past 24 hours of **successful `schedule`-triggered** `check.yml` runs via GitHub Actions API. Gaps longer than **90 minutes** yield an `::warning::` and Job Summary entry in the daily audit. `push` or manual runs never count as cron success. On 2026-11-06, direct API readback exposed a maximum 468.8-minute gap in the preceding 24 hours and only three successful scheduled runs. This is an **unresolved coverage gap**, not a financial signal. GitHub scheduled runs can be delayed or dropped: an independent external heartbeat/scheduler is required for a hard hourly service-level guarantee; the daily check itself is also best-effort.
- [Weekly baseline regression](../../tests/test_weekly_context.py) now validates the human report's **orange grade band** from the baseline file without pinning its numeric score to the 2026-10-25 historical value. The 2026-11-01 68/100 human grade and the four-family technical score remain **not comparable** for automatic upgrades/downgrades.

## Historical limitations
The [ex-post diagnostic](../../reports/expost_latest.json) reports revised-value performance with look-ahead risk, not real-time historical predictive accuracy. [ALFRED smoke](../../reports/alfred_smoke.json) has authenticated some historical as-of snapshots but earlier credit and 2008 dates are missing in the public access path; classify historical **unassessability** separately from true model misses. Full 2007–2026 weekly as-of collection is being tested [here](https://github.com/lican1213/financial-crisis-early-warning/actions/runs/40802656579); its completion must be verified before publishing forecasting accuracy. ICE MOVE direct quote and Treasury order-book depth require appropriately licensed access.

## One-time authorized FRED historical access
For full original as-published vintages beyond the incomplete public ALFRED endpoint, the owner must obtain [a FRED API key](https://fred.stlouisfed.org/docs/api/api_key.html), set it as the repository Actions Secret `FRED_API_KEY` (never in source or chat), and manually invoke [Authorized original-vintage ALFRED PIT benchmark](../../.github/workflows/alfred-authorized.yml). The workflow runs all as-published date-level vintages, performs original-release anti-leakage checks, computes event observability and the chronological benchmark, and commits only aggregate report data. This is a **manual authorization gate**, not a scheduled job that can be claimed operational without its actual Actions run.

## 2026-11-16 — canonical ChatGPT hourly condition-watch runbook

The existing hourly condition-watch remains enabled; no weekly report, extra task, reduced cadence, direct webhook, or delivery acknowledgement is introduced. Keep the automation prompt short and this document as operational reference, but the four hard gates and fallback must be self-contained in the prompt.

1. Read main's [read-only feed](../../data/chatgpt_feed.json) first. Validate schema `fcews.chatgpt.readonly.v1`, candidate count/list, observed dates, monitor health, historical weekly grade and non-comparability. Cross-check [health](../../data/health.json), [latest check](../../data/latest_check.json), [outbox](../../data/outbox.json) and last successful scheduled check.yml run when available; retrieve [observations](../../data/observations.json), [volatility context](../../data/volatility_context.json), [short-term funding context](../../data/stfm_context.json) and [weekly baseline](../../data/weekly_baseline.json) only as needed. Do not repeatedly read the entire MOC or duplicate large files.
2. Independently verify current primary-source financial risk evidence and newly reported regulatory/institutional events on every cycle. If connector fails, try public raw JSON once; if unavailable/stale, or last scheduled success is >90 minutes old or unknown, continue directly to official sources rather than aborting or retrying indefinitely. Use observation and release dates, not file modification dates, as market evidence. Sources: [OFR FSI](https://www.financialresearch.gov/financial-stress-index/), [FRED](https://fred.stlouisfed.org/), [Chicago Fed NFCI](https://www.chicagofed.org/research/data/nfci/current-data), [NY Fed reference rates](https://www.newyorkfed.org/markets/reference-rates), [Cboe VIX](https://www.cboe.com/tradable-products/vix/), [US Treasury rates](https://home.treasury.gov/resource-center/data-chart-center/interest-rates), relevant central banks, regulators, exchanges, issuers and energy authorities. Check OFR FSI, STLFSI4, NFCI/ANFCI, HY OAS, VIX/MOVE and volatility term structure, SOFR/repo and dollar liquidity, long Treasury yields and liquidity, major equity drawdowns, bank/fund/sovereign/payment events, private credit/CRE, material energy disruptions and emergency central-bank measures. Missing licensed MOVE is missing, not a substitute realized-volatility measure.
3. Notify only with newly verified material evidence of (a) significant comparable overall risk upgrade, (b) at least two independent indicator families simultaneously crossing historical stress ranges, (c) a verified institution/sovereign/repo/payment event with credible cross-market contagion, or (d) rapid recovery sufficient for a comparable overall downgrade. Candidate Issues and feed notification flags are not authorization alone. Deduplicate against published alerts and outbox; require materially new evidence for follow-ups. No headline-only rumor, ordinary single-day move, single indicator, or operational error triggers notice. On qualifying alerts give event, primary evidence with dated links, risk grade and confidence, three priorities for next 72 hours, and proportionate investor do/don't actions. Otherwise suppress all output, including calm-run summaries and pure operational status.
4. The stopped 2026-11-08 orange 70/100 six-factor human report is historical only. No automatic new weekly scores and no automatic downgrade from technical green; the scales are uncalibrated. Research fields (US employment/yield curves/IG spreads, NBS PMI/property, PBOC credit/mortgages, staffing issuer reports) are context only, never alert authority; retain nulls for unvalidated scores and original-release timestamps. Confirm original sources before interpreting; do not fabricate national turning points or equate different mortgage measures.
5. Treat each connector/source failure as a bounded operational problem; partial coverage does not imply market safety. No promise of an independent hourly SLA or exactly-once ChatGPT receipt. Escalate only actual qualifying financial evidence. The 2026-11-16 platform-side generic scheduled-task failure has no exposed root-cause log; prompt simplification is a mitigation, not proof the runtime failure has been fixed.

### 2026-11-16 — independent confirmation and empty-feed non-veto
The feed's default false flag and empty candidate list only report the GitHub channel; neither vetoes newly corroborated official events or the four independent user gates. The automatic two-family candidate gate now requires at least two distinct direct channels (credit, volatility, funding) crossing existing numeric cutoffs on the same observation date. System composites (OFR FSI, STLFSI4, NFCI/ANFCI) corroborate and remain in the historical raw technical grade; never count a composite plus its component as two independent votes. Same-date matching is a conservative automated rule, not a claim of statistical independence; independently verified overlapping stress windows and cross-market events remain eligible for manual review. No numeric cutoff changed. Old backtest alert counts are not validation of the revised gate. Source: [OFR methodology](https://www.financialresearch.gov/financial-stress-index/).

### 2026-11-16 — operational heartbeat and alert lifecycle
- The hourly workflow now publishes a small separate `data/poll_heartbeat.json` after collection, persistence and bridge steps. It intentionally advances on unchanged evidence; it does not change evidence fingerprints or trigger any market notification. Read its schema `fcews.poll_heartbeat.v1`, trigger, stage outcomes, health, evidence SHA and last successful scheduled poll clock. A manual/push success cannot refresh the scheduled clock; missing receipt, failed stage, partial coverage, or >90-minute scheduled gap call for independent official evidence. A receipt is a published stage-level checkpoint, not a separate scheduler SLA, a guaranteed final Actions conclusion or a ChatGPT delivery receipt. GitHub API verification remains preferable when available. Receipt writes add one tiny commit per completed attempt (no new workflow or risk candidate). An independent outside Healthchecks-type service still requires an owner-provisioned endpoint and separate operational routing; not deployed by this change.
- [Core](../../src/fcews/core.py) now keeps an active direct-stress episode across missing/asynchronous observations. Only newer aligned observations for all active channels with fewer than two critical rearm it. A newly confirmed direct channel emits a distinct candidate once; unchanged episode evidence does not repeat. This is lifecycle dedup, not a user-alert authorization, severity reweighting or historically calibrated threshold change. No cron or user notification frequency changes.

### 2026-11-16 — natural-schedule identity, re-entry and exact-date joins
Only a successful `schedule` with run attempt 1 refreshes the natural scheduled clock. A retry can refresh actual poll completion but not natural cadence. Legacy heartbeat clocks without natural-attempt attestation are reset to unknown on upgrade; first-attempt-only API audits may conservatively exclude a rerun whose earlier attempt succeeded. The hourly workflow uses GitHub's `queue: max` and current main checkout, preserving existing cron and serialized writes. Earlier workflow definitions already attached to old runs cannot be retroactively changed. Prefer a fresh workflow_dispatch rather than rerunning legacy definitions; manual recovery never certifies natural cadence.
Direct channel states are independently dated: an observed newer normal value resolves that channel; a subsequent same-date confirmed pair including a re-entering channel can generate a new candidate. Missing/expired/asynchronous evidence does not by itself resolve an episode. Recent source observations (existing 7-calendar-day TTL, exact dates only) permit aligning delayed releases without forward-fill; a newer normal observation invalidates older pressure. First retrieval is not original publication. Replay selects dated release vintages separately. See [history](../../src/fcews/history.py), [core](../../src/fcews/core.py), [PIT replay](../../src/fcews/backtest.py) and [reference projects](../../wiki/sources/reference-projects.md). No cutoff changes. GitHub outbox delivered records acknowledge candidate Issues, not a ChatGPT end-user delivery; dedup must distinguish them. New candidate evidence does not authorize user alert without the four gates. Independent scheduler and licensed market data remain separate dependencies.
