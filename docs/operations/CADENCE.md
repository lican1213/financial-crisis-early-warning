## Delivery boundary
The daily research workflow publishes its official observations **before** rebuilding and committing the read-only ChatGPT feed. An initially stale feed after NBS succeeded revealed a real ordering defect (FAIL-045). The bridge refresh is a separate post-persistence step; GitHub can still produce concurrent update conflicts, which must fail visibly rather than be interpreted as a market crisis. [Run and audit evidence](../../wiki/operations/INCIDENTS.md).

The [read-only ChatGPT bridge](../../src/fcews/bridge.py) exposes only research snapshot freshness, source observation dates, and null China/company scores. Even a fabricated `notification_authorized=true` field in a research file cannot authorize an alert; [bridge regression tests](../../tests/test_bridge.py) prove the separation.

The research workflow is context-only and never increases independent systemic stress families or sends ChatGPT notifications. Official-host acceptance of a manually entered China/company release is not proof of the numeric statistic; verify underlying tables before claims. See [leading research gate](../../wiki/datasets/leading-research.md).

The [ChatGPT feed](../../data/chatgpt_feed.json) is **poll-only**, not a push event or confirmed end-user receipt. [GitHub Issue canary #11](https://github.com/lican1213/financial-crisis-early-warning/issues/11) verifies GitHub create/read/close only; ChatGPT cannot emit an exact-once acknowledgement to the repository. The hourly ChatGPT task remains enabled. We deliberately keep user-visible responses silent without one of the four qualifying systemic changes.

## Data quality gates
A GitHub Action run marked success is not sufficient evidence of market source coverage; inspect `data/health.json`. **degraded** means fewer than three fresh live independent risk families, an operational incident, not calm markets. Context-only Cboe/MOVE substitutes do not independently increase family counts until calibration. No private holdings, credentials or user-specific assets are committed to the currently public GitHub repository.

### 2026-11-09 paused-report and schedule mitigation
- The former weekly report automation is disabled at the user's request. Do not reactivate it or automatically fabricate weekly scores. Leave the saved 2026-11-08 subjective orange/70 baseline intact and technically incomparable.
- A second `check.yml` GitHub scheduled slot at minute 43 mitigates long gaps but shares the same platform failure domain; no hard per-hour guarantee. The independent ChatGPT condition-watch still obtains official evidence when the repository feed is stale; **true silence** unless one of the original user alert conditions is independently met. An external heartbeat/scheduler is still an open P0.
- Research source context and provisional China/company records remain **non-alert** data. No incomplete release coverage may be called score zero.

### 2026-11-06 operational guardrails
- A **healthy** collection needs all four actual live families (system, credit, volatility, funding), no unresolved collection errors and no unusually old official source dates. Three live families, or an overdue series, are **partial**; fewer than three are **degraded**. Missing live evidence is not filled by cached observations. An FRED SOFR/TGCR request may fail while the same series is successfully collected from the independent official NY Fed endpoint (and vice versa); the original error is retained under `recovered_source_errors`, not confused with unavailable data.
- [Source age check](../../src/fcews/quality.py) flags daily observations more than **three weekdays** behind and weekly observations more than **eight weekdays** behind as **operational heuristics**. The count excludes weekends but not public holidays or publisher-specific release calendars; it does not claim an exact publication timestamp and cannot trigger a market-risk alert.
- [Actual schedule delivery audit](../../src/fcews/schedule_health.py) checks the past 24 hours of **successful `schedule`-triggered** `check.yml` runs via GitHub Actions API. Gaps longer than **90 minutes** yield an `::warning::` and Job Summary entry in the daily audit. `push` or manual runs never count as cron success. On 2026-11-06, direct API readback exposed a maximum 468.8-minute gap in the preceding 24 hours and only three successful scheduled runs. This is an **unresolved coverage gap**, not a financial signal. GitHub scheduled runs can be delayed or dropped: an independent external heartbeat/scheduler is required for a hard hourly service-level guarantee; the daily check itself is also best-effort.
- [Weekly baseline regression](../../tests/test_weekly_context.py) now validates the human report's **orange grade band** from the baseline file without pinning its numeric score to the 2026-10-25 historical value. The 2026-11-01 68/100 human grade and the four-family technical score remain **not comparable** for automatic upgrades/downgrades.

## Historical limitations
The [ex-post diagnostic](../../reports/expost_latest.json) reports revised-value performance with look-ahead risk, not real-time historical predictive accuracy. [ALFRED smoke](../../reports/alfred_smoke.json) has authenticated some historical as-of snapshots but earlier credit and 2008 dates are missing in the public access path; classify historical **unassessability** separately from true model misses. Full 2007–2026 weekly as-of collection is being tested [here](https://github.com/lican1213/financial-crisis-early-warning/actions/runs/40802656579); its completion must be verified before publishing forecasting accuracy. ICE MOVE direct quote and Treasury order-book depth require appropriately licensed access.

## One-time authorized FRED historical access
For full original as-published vintages beyond the incomplete public ALFRED endpoint, the owner must obtain [a FRED API key](https://fred.stlouisfed.org/docs/api/api_key.html), set it as the repository Actions Secret `FRED_API_KEY` (never in source or chat), and manually invoke [Authorized original-vintage ALFRED PIT benchmark](../../.github/workflows/alfred-authorized.yml). The workflow runs all as-published date-level vintages, performs original-release anti-leakage checks, computes event observability and the chronological benchmark, and commits only aggregate report data. This is a **manual authorization gate**, not a scheduled job that can be claimed operational without its actual Actions run.
